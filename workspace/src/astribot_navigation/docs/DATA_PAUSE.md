# 导航停车等待与原目标恢复

> **2026-11-20 已废弃。** 网页层的暂停—恢复—重新提交状态机已删除，重试只由 Nav2 行为树负责。现行说明见 [CONTINUOUS_NAVIGATION.md](CONTINUOUS_NAVIGATION.md) 的“2026-11-20 收敛为单一决策链”。下文仅保留为历史记录。

导航保留最近 10 帧融合扫描，每次选择有同刻 TF 的最新有效帧。只有新的扫描才能更新定位质量，时效按该帧实际接收时间计算。

全局规划与局部控制都使用静态地图和实时障碍点云。单条轨迹受阻时，DWB 继续比较前进、横移、后退和转向轨迹。浏览器转发控制器选出的速度；暂停恢复不依赖上一次倒车方向的通畅程度。

扫描、TF、定位更新或执行器状态短暂延迟时，活动目标同样进入等待。底盘确认静止、旧动作结束且各项数据连续就绪 2 秒后，从当前位置向原目标重新规划。相对微调仍使用最初的里程计目标。

普通导航暂时无路或跟踪失败时，在原 Nav2 动作内等待 1 秒，再从当前位置规划。等待期间向底盘发送零速度。动作反馈中断或导航准备超时，沿用停车保留目标的流程。页面显示本次暂停的原因和连续就绪时间。

手动取消、浏览器控制许可过期、底盘报告故障或失去控制权、定位明确失配和里程计历史中断仍按原流程处理。

## 2026-10-29 边界抖动调整

当日日志 TF 延迟约 0.52 s、派生扫描约 0.83 s，触发旧 0.5/0.8 s 门槛和反复 2 s 恢复等待。现将 TF 源容许上限设为 0.8 s、扫描最老源设为 1.0 s，保留原始源与全部接收流 0.5 s 看门狗、定位匹配与 SDK 保护。超限仍停车，原暂停恢复状态机不变。

已取消或替换动作的同页迟到心跳不再显示许可失效，不延长当前或旧任务许可；真正过期仍不可复活。重启导航并整页刷新加载，未进行实际运动验证。
